## 2. 발표 목표와 구현 단계

2019-04-04 인제산불 환경에서 `환경 상태 → 총괄 판단 → Task/후보 → 물리 사전필터 → Local 경로 평가 → Safety → 실행 → 도착 → 관측 → 환경 적용 → 재판단/재배치 → 공식 기준 F1 → 진화 행동 F2 → 재관측/종료` 폐루프를 보여준다. **F1과 F2까지 연결되어야 최종 발표 목표 달성**이다. 현재 기준 자료·환경 효과 모델이 없으면 계약 자리와 미완료 상태만 구현한다. 기존 웹 애니메이션 성공이나 UAV 고정 응답을 완료로 대체하지 않는다.

이번 총괄 단독 작업은 영속 Task/event/decision/attempt 기록, 상태 전이, 예약, 내부 중복 억제, UNKNOWN/HOLD/수동 해소, 조회 API, deterministic 검증 및 시험 fixture로 제한할 수 있다. 외부 실제 연동은 별도 게이트로 관리한다.

## 3. 환경·공간·풍속 계약

환경·통합 담당과 **하나의 authoritative `run_id`**가 가진 상태에 대해 `READ`(변경 없는 원자적 전체 snapshot), `ADVANCE`(명시적 simulation 진행), `APPLY`(관측·진화 이벤트 적용)를 합의한다. API 이름·tick 길이·version 증가 규칙은 팀이 정한다. 웹과 총괄이 각자 환경 모델을 생성하지 않는다. snapshot은 `run_id`, `state_version`, `simulation_time`, `map_version`, 화재 상태/버전, 풍속값 `wind_ms`·유효 시각, 좌표계·수직 datum을 연결해야 한다. 중복·역순 검사는 동일 `run_id` 안에서 수행하며 결번과 새 실행 전환은 별도로 다룬다. 지금 환경 API의 간략 metadata 조회나 connector 조회를 이 계약이 구현된 것으로 간주하지 않는다.

환경팀이 제공할 새 인제 맵에는 재현 지역의 지형과 소방서 위치가 포함될 예정이다. 총괄은 소방서·화재·도로망·grid·지도 원점과 경계를 코드에 직접 쓰지 않고 맵 metadata와 자원 registry를 참조한다. 총괄은 경로 계획을 위해 DEM 본문을 직접 읽지 않지만, UAV가 사용한 `terrain_dataset_id/version`과 좌표계·수직 datum·유효성은 판단 근거로 기록한다. 새 맵 반영 후 WGS84, Gazebo local, PX4, 도로망, 지형, 소방서, 원통 좌표가 같은 공간에 놓이는지 담당별 검증 결과를 대조한다. 지금 코드에는 고정 원점/좌표와 NoData 대체·범위 바깥 보정이 있으므로 이러한 대체값으로 clearance가 검증되었다고 처리하지 않는다. 실제 맵 부재 시 `계약 구현 / fixture 검증 / 실제 지도 대기`를 분리한다.

## 4. UAV 목표 고도·route 계약과 후보 순서

### 4.1 현재 구현된 단일 목표 계약

총괄은 현재 단일 목표의 `lat`, `lon`, `alt_m_amsl`, `target_agl_m`, `wind_ms`를 UAV에 전달하는 것으로 갱신한다.

- `alt_m_amsl`: **목표 지점 지면의 해발고도**다. 비행고도 자체가 아니다. 누락하면 UAV는 `REJECT / TARGET_ALTITUDE_UNKNOWN`을 반환한다.
- `target_agl_m`: 임무가 요구하는 지면 위 높이다. 기본값은 80m지만, 총괄은 가능한 한 임무값을 명시한다.
- UAV의 최종 목표 비행고도: `alt_m_amsl + target_agl_m + AGL_MARGIN_M(10m)`다. 기본 임무라면 지면보다 90m 위다.
- 총괄은 80m나 10m를 `alt_m_amsl`에 미리 더하지 않는다. UAV도 10m를 두 번 더하지 않는다.
- `wind_ms`: 같은 판단 시점의 환경 snapshot에서 전달한다. 없으면 0이나 Mock 내부값으로 대체하지 않고 UAV의 `WIND_UNKNOWN`을 보존한다.

위 의미는 `origin/feat/uav-agent` 커밋 `6b052a0`의 `models.py`, `config.py`, `evaluator.py`에 반영되어 있다. 그러나 공통 `Assignment`와 총괄 Adapter가 `target_agl_m`을 실제로 전달하는지는 구현 시 최신 브랜치에서 다시 검사한다. 기존 단일 목표 API와 미래 route API의 의미를 섞지 않는다.

### 4.2 수행 가능성의 잠정 수치

UAV 답변에 따라 다음 시뮬레이션 값을 사용한다. 실제 기체 성능값으로 표현하지 않는다.

- 기체: Gazebo `x500`.
- 풍속: 8m/s 이상 10m/s 미만은 `COUNTER / MODERATE_WIND`, 10m/s 이상은 `REJECT / HIGH_WIND`.
- 복귀 후 배터리 예비량: 15%. 예상 잔량 0% 미만은 `REJECT / LOW_BATTERY`, 0~15%는 `COUNTER / RETURN_MARGIN_INSUFFICIENT`.
- 순항속도: 10m/s, 상승속도: 3m/s.
- 편도 ETA: `수평거리/10 + 상승량/3`. 상승량은 `최종 목표 비행고도 - 현재 AMSL`의 양수 부분이다.
- 관측 체류시간: 기본 60초.
- 배터리 소모율 `0.033%/s`는 추정값이다. 하강·이륙 시간과 실제 바람 보정은 현재 ETA에 충분히 반영되지 않았다.

기본 예시인 현재 AMSL 235m, 목표 지면 804m, 목표 AGL 80m라면 최종 목표는 894m이고 상승량은 659m다. 편도 약 9.8km·배터리 95% 조건의 답변 계산은 복귀 후 13.8%로 `COUNTER`다. 이 예시를 모든 발화 위치의 기체 반경이나 실제 항속거리로 일반화하지 않는다.

비행 중 1초 주기의 복귀 여유 확인과 부족 시 `FAILED / RETURN_MARGIN_INSUFFICIENT` 후 복귀 흐름은 최신 UAV 코드에 추가되었다. 다만 실제 PX4 failsafe·통신 품질은 여전히 완전한 텔레메트리 근거가 아니며, 복귀 성공·READY를 총괄이 별도로 확인해야 한다. UAV의 `COMPLETED`는 관측 종료 시점이고 복귀 중일 수 있으므로 Task 목적 완료와 자원 반납을 구분한다.

### 4.3 지형 추종 책임 배분 확정 — 구현 대기

**UAV Agent가 환경팀의 DEM을 직접 읽고**, 출발지부터 목표까지 경유지와 비행고도를 생성하며 경로 전체를 평가·실행한다. 총괄은 목적지, 임무 AGL, 환경 snapshot과 임무 조건을 제공하고 `ACCEPT / REJECT / COUNTER`, 경로 식별정보와 평가 요약을 받아 후보 선택·Safety 요청·재할당을 관리한다. 이 책임 배분은 2026-09-29 총괄 설계 범위를 정리하면서 확정했다. 샘플링 100m와 AGL 허용오차 ±10m는 구현·Gazebo 검증 전까지 잠정값이다.

환경 → UAV의 DEM 제공 경계는 별도 계약으로 정한다. 환경팀이 소유한 dataset ID/version, 파일 또는 API 접근 방식, 수평·수직 datum, NoData, 유효범위와 Gazebo 월드가 같은 자료에서 생성됐는지를 명시한다. UAV가 저장소 경로를 임의로 직접 참조하거나 오래된 DEM을 사용하는 방식은 피한다. 총괄은 DEM 본문이나 경유지를 생성하지 않고, UAV가 반환한 route ID/version/hash와 평가 결과를 받아 Safety 승인과 실행 요청이 동일 경로를 참조하도록 관리한다.

현재 확인된 UAV 코드에는 완성된 DEM route planner가 없고 단일 목표만 평가·실행한다. 따라서 다음을 구분한다.

1. **확정·구현됨:** 단일 목표의 지면 AMSL + 목표 AGL + 10m 계산.
2. **책임 확정·미구현:** UAV Agent의 DEM 직접 조회, 다중 경유지 생성, 전체 경로 평가·실행.
3. **잠정 제안값:** 100m 샘플링, ±10m 허용오차.
4. **계약 합의 필요:** DEM 접근 방식, route schema, 고도 datum, NoData, 경유지 사이 검사, Safety 검증, 샘플링/오차 최종값.

V자형 골짜기와 능선은 UAV route planner가 처리하더라도 지형을 기계적으로 따라 급강하·급상승하는 경로만 생성해서는 안 된다. 구간 전체의 최소 여유, 상승·하강률, 속도, 최대고도, 배터리·복귀 여유와 PX4의 실제 궤적을 검사한다. 골짜기 횡단에서 AGL이 목표보다 커지는 것을 허용할지, `±10m`를 엄격히 적용해 하강할지는 UAV·Safety가 정해야 한다. 지면고도를 허위로 바꾸거나 `+10m`를 중복 적용하는 방식은 금지한다.

확정 흐름은 `총괄 후보·목표 제안 → UAV Local route 생성·전체 평가 → ACCEPT → Safety ALLOW → 동일 route execute`다. `REJECT`는 다음 후보/HOLD, `COUNTER`는 수정 필드가 명확할 때 총괄이 새 `decision_id`와 수정 임무조건을 발급하고 UAV가 새 route version/hash를 생성해 재평가·재승인한다. 수정값 없는 권고는 자동 실행하지 않는다.

## 5. Safety, ID 및 실행 장부의 일관된 순서

`task_id`, `decision_id`, `execution_attempt_id`, `resource_id`, `route_id/version/hash`를 구분한다. ID 발급 자체는 명령 송신이 아니다. 권장 순서는 다음과 같다.

1. 총괄이 Task·자원 후보와 목표 조건을 만들고, UAV가 생성한 route와 Local 평가를 받는다. `REJECT`는 예약 이전이므로 해제할 예약이 없다.
2. `ACCEPT`한 경로와 함께 `execution_attempt_id`를 **발급**하고 Safety에 정확히 그 ID·Task·자원·route hash·풍속/지도 snapshot을 입력한다.
3. Safety는 상태, 단위, 좌표계/datum, 유효 지형, 확인된 물리 한계, Local ACCEPT route와 승인 route와 실제 송신 route의 동일성 및 정책을 검사한다. 필수 정보가 없으면 ALLOW하지 않는다.
4. ALLOW 후 자원을 경쟁 없이 예약하고 attempt/승인·route·중복키를 **송신 전에 영속 저장**한다. 저장·예약 실패 시 송신하지 않는다. 구현이 예약을 먼저 잡아야 한다면 그 준비 예약은 기한·취소 상태를 갖고 ALLOW 실패 시 정리한다.
5. 저장된 정확한 명령을 한 번 전송하고 ACK/상태를 대조한다. timeout·응답 유실·서비스 재시작 후 조회 불능은 `UNKNOWN`; 점유 유지, 자동 재전송·재출동 금지다. 실제 상태 확인 또는 명시적 수동 해소로만 정리한다.

동일 Task의 중복 접수는 총괄 내부에서 한 decision/attempt로 수렴시킨다. 네트워크 경계를 건너 동일 명령이 최대 한 번만 실행되려면 UAV/실행 Connector가 idempotency key와 안정적인 attempt 상태 조회를 지원해야 한다. 이 지원 전에는 **총괄 내부 중복 억제만 검증됨**으로 보고한다.

## 6. 두 상태축, 완료와 해제

공통 `TaskState`를 임의로 재정의하지 말고 총괄 내부의 Task 목적 상태와 execution substatus를 분리한다.

| 사건 | Task 의미 | 실행 의미 | 자원 |
| --- | --- | --- | --- |
| 평가 전·Local 평가 | 대기/평가 | 아직 실행 없음 | 예약 전 |
| Local ACCEPT·Safety ALLOW | 승인된 실행 후보 | 미전송 attempt | 송신 전 예약 |
| 송신 및 ACK | 목적 미완료 | REQUESTED/STARTED | 점유 |
| 응답 유실·조회 불능 | 완료 아님 | UNKNOWN | 점유 유지 |
| 물리 도착 확인 | 임무 목적은 별도 확인 | ARRIVED | 임무/복귀에 따라 점유 |
| 유효한 관측 확인 | 관측 Task 조건 일부/전부 충족 | OBSERVED | 조건에 따라 점유 |
| 환경 적용 ACK | 환경 반영 확인 | APPLIED | 조건에 따라 점유 |
| 목적조건 확인 | Task 완료 가능 | COMPLETED | **자원 READY/반납 확인 후** 해제 |

모든 Task가 환경 ACK를 요구하는 것은 아니다. 정찰/관측/진화 등 Task 종류별로 완료조건을 명시하고, 환경 갱신을 요구하는 Task는 적용 ACK까지 검증한다. 출동 명령 수락, 물리 도착, 관측값 생성, 환경 ACK와 Task 완료를 별개 event로 기록한다. 기체가 복귀 중이면 Task 목적이 끝나도 다른 임무에 투입할 수 없으며 자원 점유 해제는 READY/인계 확인 계약에 따른다.

## 7. 두 시계와 ETA

HTTP·서비스·LLM timeout은 실제 경과시간 기준이다. 2019년 사건시각, 시나리오 상태, 임무의 역사적 deadline은 simulation clock 기준이다. ETA는 절대시각이 아닌 **소요시간인지 명시**하고 simulation 배속/정지 여부와 결합하는 계약 없이 두 시계의 timestamp를 비교하지 않는다. 현재 UAV evaluator는 UTC 현재 시각에 deadline을 비교하므로 2019년 timestamp를 그대로 전달하면 유효한 역사적 임무도 거절될 수 있다. UAV팀과 `remaining_time_s`, `deadline_simulation_time` 또는 clock context 중 지원 가능한 방식을 결정하고, 수정 전에는 simulation deadline 기반 실운용 통과를 주장하지 않는다.

현재 UAV의 잠정 ETA 식은 `수평거리/10m/s + 상승량/3m/s`다. 이는 소요시간 추정값이며, 하강·이륙·경로 중간 지형·가감속을 완전히 포함하지 않는다. 총괄은 이 값을 절대 도착시각이나 실제 성능 보증으로 바꾸지 않고 원문과 계산 기준 버전을 함께 기록한다.

## 8. 관측, 재판단과 우선순위

모의 관측은 물리 도착을 **별도로 확인한 뒤에만** 생성한다. `observation_id`, Task/자원/attempt, `SIMULATED`, 센서 종류·profile, 관측 위치·시각과 simulation time, coverage/footprint, 탐지/미탐지/실패 사유를 보존한다. 센서 profile 미합의 상태에서는 인터페이스와 **명시적 시험용 profile**만 둔다. 300m 고정 반경을 운영 규칙으로 넣지 않는다. 현 UAV의 일정 시간 후 고정 312.5℃·hotspot은 연결 mock이며 도착·실제 탐지·환경 효과의 근거가 아니다.

**이번에 채택한 시험용 fixture**는 아래와 같다. 실제 ADAIR 기체에 H20T가 장착되었다는 주장은 아니다. 이 값은 모의 센서의 테스트 영역을 만드는 데에만 사용하고, Safety의 비행경로·화재 진압범위·실제 관측 신뢰도로 전용하지 않는다.

```yaml
sensor_profile_id: TEST_THERMAL_50M_V1
source: SIMULATED
status: TEST_ONLY
sensor_type: THERMAL
agl_m: 50
view_direction: NADIR
footprint_shape: RECTANGLE
footprint_width_m: 30
footprint_height_m: 25
reference_payload: H20T_CLASS_EXAMPLE  # 실제 탑재 장비 미확인
basis: IDEALIZED_DIAGONAL_FOV_GEOMETRY  # 평탄지·수직 촬영·영상 종횡비 가정
```

산출 근거: 제조사 H20T 열화상 DFOV 40.6°, 영상 640×512를 사용하면, 50m 상공의 이상적인 대각선 지상 길이 `2×50×tan(40.6°/2) ≈ 37.0m`, 종횡비 5:4의 직사각형은 약 **28.9×23.1m**다. 위 **30×25m는 이 값을 보기 쉽게 반올림한 시험 설정이며 정확한 제조사 관측범위가 아니다**. H30T의 45.2°/1280×1024로 같은 계산을 하면 약 32.5×26.0m이므로 장비가 바뀌면 다시 계산한다. 출처: [DJI H20T 사양](https://www.dji.com/support/product/zenmuse-h20-series), [DJI H30T 사양](https://enterprise.dji.com/zenmuse-h30-series/specs). 국내 연구도 관측 면적을 고도와 시야각에 따른 투영량으로 다룬다: [박명훈 외(2026)](https://www.kci.go.kr/kciportal/ci/sereArticleSearch/ciSereArtiView.kci?sereArticleSearchBean.artiId=ART003326349).

이 rectangle은 **정지한 기체의 단일 수직 촬영 프레임**을 가정한다. 관측 위치를 중심으로 지도상 사각형의 방향(heading)과 좌표 변환을 fixture에 포함하며, footprint 안에 화재 정보가 있는 경우에도 실제 탐지가 보장되는 것은 아니다. 지형 경사·수목/연기 차폐·짐벌 각도·줌·센서 탐지율과 비행 중 지면으로부터의 실제 높이는 이 fixture에 반영되지 않는다. 실제 센서 profile, 관측 경로 및 탐지 판정은 UAV·환경팀 계약 후 교체한다. 반경 15m로 자동 환산하지 않는다. 기존 `radius`만 받는 API가 있다면 신규 shape 계약을 먼저 협의한다.

이 50m 센서 fixture는 최신 UAV 기본 임무고도와 별개다. UAV의 기본 `target_agl_m=80m`에 10m 여유를 더하면 기본 명령 높이는 지면보다 90m이므로, 기본 비행에서 위 30×25m footprint를 그대로 사용하지 않는다. 90m 또는 실제 관측 AGL에 맞춰 다시 계산하거나, 센서 시험에서만 50m를 명시적으로 요청한다.

**환경팀과 협의된 신규 입력:** 새 지도에서 **불타는 구역 경계를 따라 아직 불타지 않은 위험지역 약 10칸**을 표시할 예정이다. 총괄은 `fire_cells`와 `risk_zone`을 **같은 지도·같은 환경 snapshot에 겹쳐** 위험도가 어디에 분포하는지 판단한다. 현재 `connectors/fire_connector.py`는 UNBURNED 셀 중 `risk_score >= 0.4`를 내림차순 정렬하고 최대 300개까지 내보내므로, 이 코드만으로는 신규 맵에서 정확히 10칸 또는 경계의 연속성이 보장되지 않는다. 현재 웹은 화면에 `risk_zone` 좌표만 보여 주고 점수는 전달하지 않으며, 자동 출동 대상은 `fire_cells`에서 고른다. **현재 총괄이 위험지역 분포를 분석해 임무에 반영한다는 기능은 확인되지 않았다.**

총괄의 판단 입력에는 해당 셀의 `cell_id`, 격자 좌표와 지도상 실제 위치·셀 크기/인접관계, `fire_state=UNBURNED`, `risk_score`, `run_id/state_version/simulation_time/map_version`이 필요하다. 불타는 셀과 위험 셀의 접경·연속 구역, 바람 방향, 소방서·도로·시설의 지도상 위치를 **시각화하고 판단 근거에 기록**한다. 현재 환경 위험점수는 풍향 인접성·경사·연료량을 이미 반영하는 임시 모형이므로 총괄이 같은 요소를 점수에 다시 더하거나 새 등급 기준을 만들지 않는다. `fire_cells`의 고정 1.0과 위험지역 점수를 섞어 화재 규모·진화 우선순위·출동 수량을 계산하지 않는다. 단순히 위험 셀 10개를 각각 독립 출동 Task 10건으로 바꾸거나, 관측만으로 UNBURNED를 BURNING으로 변경하지 않는다.

**사용자 확정 판단 방식:** 환경팀과 구두 협의된 화선 주변 위험 셀 약 10칸의 위험도와, **소방청의 공식 우선 보호 기준에 해당하는 대상의 지도상 위치**를 결합해 총괄이 판단한다. 이를 구현 담당자는 다음의 두 입력 계약과 계산·판단으로 구체화한다.

1. 환경의 위험 셀 각각에 `cell_id`, 점수·상태, cell geometry/지도 좌표, snapshot ID를 붙인다. 소방청 기준 쪽은 원문 자료의 명칭·버전·시행/적용일, 대상 유형·공식 우선순위(문서에 명시되어 있을 때만), 실제 인제 지도에서 확인된 대상 ID·위치/경계를 별도의 **보호대상 registry**로 받는다. 새 맵에 보호대상 좌표가 없다면 소방서 좌표만으로 대신하지 않는다.
2. 같은 좌표계로 변환한 뒤 **각 위험 셀과 각 보호대상 경계의 최소 거리(m)**를 계산한다. 점 중심 거리만으로 넓은 시설이나 위험 셀의 가장자리를 잘못 판단하지 않는다. `cell_id ↔ protected_site_id`, 거리, 위험점수, 공식 대상 유형/순위, 데이터 버전, 좌표계와 계산 방식을 결정 근거에 보존한다. 대상 위치·경계가 없거나 좌표 변환이 검증되지 않으면 거리를 만들어내지 않는다. 출동 경로의 이동시간/접근성은 이 직선거리와 별개로 Local/도로망 평가에서 구한다.
3. 총괄은 위험도와 보호대상까지의 거리, **확인된 공식 우선순위**, 현재 화선 및 다른 Task 상태를 함께 제시하고 어느 구역을 먼저 관측·보호·대응할지 결정한다. LLM이 이를 제안할 수 있으나 확인된 입력/출처와 Safety·Local 검증을 거친다. `위험점수 × 거리` 같은 임의 합성식, 임의 가중치, 임의 보호등급은 만들지 않는다. 두 후보의 위험도·거리·공식 순위가 서로 엇갈리는 경우 합의된 비교 규칙이 없으면 이유를 기록하고 HOLD/수동 판단으로 넘긴다. **위험지역이 가깝다는 사실만으로 소방차 대수나 진화량을 확정하지 않는다.**

소방청의 2025년 공식 보도자료는 주택, 문화재 및 국가 중요시설 보호를 산림화재 대응의 핵심으로 설명한다. 그러나 이 보도자료에는 이들 사이의 **수치 순위·거리별 가중치·인제 보호대상 좌표가 없다**. 따라서 이를 확정된 순위표로 바꾸지 말고 실제 적용할 소방청 원문 기준/안내서와 환경팀의 새 지도 보호대상 레이어를 확인해야 한다. 자료: [소방청 보도자료(대한민국 정책브리핑에 전재)](https://m.korea.kr/briefing/pressReleaseView.do?newsId=156676891).

**2019년 인제 재현 참고자료: 《2019 강원 산불백서: 하나되어 맞선 강원산불》, 강원도소방본부, 2019년 12월.** 이번에 제공된 백서의 인쇄면 140~146쪽은 인제 산불의 사건 시각, 실제 보호 대상, 대피·방어·증원·기상 제약을 기록한다. 인쇄면 141쪽의 <그림 3-13>에는 남전리 마을회관/주택, 인제휴게소, 인제상하수도사업소 위생환경처리장 등 주요 시설이 **상대적 위치**로 표시된다. 같은 쪽은 가로리·남전리 주민 35명 대피와 민가 41채 등 45동 방어를 기록한다. 142~146쪽에는 4월 4일 15:06 기상악화로 소방헬기 출동 불가, 15:38 주민 대피 지시, 16:25 대응 2단계, 19:06 일몰 후 헬기 진화 중단, 야간 민가 방어 등의 사건이 있다. 인쇄면 204쪽도 인명·민가·병원·노유자 시설 등 주요시설 방어를 분석한다. 출처: [첨부 백서 PDF](sandbox:/workspace/scratch/714ba9cd3799/upload/01-board_BDMAIN28_20200408_1.pdf).

이 백서는 **인제 시나리오의 실제 사건 흐름, 보호대상 후보, 판단 전환점 및 발표 결과 비교의 근거**로 사용한다. 그러나 그림에 좌표축이 없어 지도상의 **정확한 위경도나 시설 경계를 추출할 수 없으며**, 2019년 실제 대피 인원·투입 대수·대응 단계가 2026년 공식 우선순위 산식이나 소방차 출동 공식이 되는 것은 아니다. 새 지도에 시설 위치를 올릴 때에는 별도 위치 자료로 검증한다. 시뮬레이션 시작 시 총괄에는 당시 그 시각까지 관측·신고된 정보만 주고, 백서의 **나중에 밝혀진 실제 피해/결과를 미리 판단 입력으로 주지 않는다**. 시나리오 replay의 각 사건과 반사실 판단을 구분해서 기록한다.

Task의 긴급성·deadline·미관측 시간·요구조건은 현재 공통 schema에 없다. 환경·통합과 그 정의·출처를 합의하고 **실제로 제공된 필드에 한해** 결정론적 우선순위와 동률 처리 규칙을 만든다. 다만 환경이 제공한 위험지역 지도 정보는 현재도 유효한 판단 입력이며, 다른 필드가 없다는 이유로 그 정보까지 버리거나 모든 상황을 무조건 HOLD하지 않는다. 실행 결정을 내릴 근거가 부족한 부분만 HOLD로 남긴다. `risk_score=1.0`인 BURNING 셀들을 위험 점수만으로 서열화하지 않고, 0.4 위험지역 포함 임계값을 LOW/MEDIUM/HIGH **화재 등급**으로 바꾸지 않는다. 위험지역의 위치·점수·연속성이나 화선이 바뀌면 같은 `run_id`의 새 snapshot으로 재평가한다.

## 9. 총괄 API와 LLM

총괄은 health/status, Task 접수, 외부 event 접수, 사건/Task/decision/attempt/보류 이유 조회, 수동 해소·resume를 제공한다. 이름·포트·host는 기존 웹/통합 배포와 협의하고 설정으로 주입한다. 웹의 직접 UAV evaluate/execute는 최종 시연에서 총괄·Local·Safety를 거치도록 통합 담당과 변경 계약을 만든다.

LLM은 검증된 snapshot의 ID, Task·resource ID, 허용 행동과 route/Local 결과를 받아 **계획만 제안**한다. 출력의 schema와 현재 run/state/resource/task/action/단위 일치를 deterministic validator가 검사한다. 검증 실패·timeout·부재 시 deterministic fallback, 그 판단도 불가하면 HOLD로 간다. 모델·timeout·호출/비용 한도·sampling 설정은 configuration이고 20초 기본값을 임의 결정하지 않는다. 입력/출력, 검증 실패, fallback, 채택 decision을 기록하되 secret은 제외한다. 같은 LLM 출력을 보장한다고 말하지 않고 기록한 결정을 재생해 시연 재현성을 확인한다.

## 10. F1 공식 출동 기준과 F2 진화 효과

**F1은 미완료.** 사용자가 정한 발표 전제는 **2019년 인제 화재를 재현하고, 총괄이 있었다면 2026년 기준으로 어떻게 대응할지 시뮬레이션**하는 것이다. 역사적 2019년 대응규칙을 구현할 필요는 없다. 원래 링크는 2027-07-08 시행 예정본이므로 **2026년 기준의 근거로 인용하지 않는다**. 2026년 적용 기준일(구현/시연 기준일)을 기록하고 그날 시행 중인 법률·시행령·시행규칙과 실제 자원 동원 세부기준, 담당 기관별 관할의 원문을 확보한다. `official_rule_source/version/effective_date`, 단계 판단 입력, 대응 단계, 자원 종류·수량, 예외·근거를 매핑한다. 백서 140~146쪽의 실제 출동·대피·방어 기록은 **시나리오/결과 비교 자료**이지 새 출동 대수의 계산 규칙이 아니다. 법령의 대응 단계와 소방차 정확한 대수·소방차 한 대의 진화량은 서로 다른 자료·모델 문제다. 자료 전에는 임의 `면적 X → 차량 Y대`를 만들지 않는다.

**F2도 미완료.** `web/app.py`의 진화 경로는 화면/auto done이 `UNBURNED`를 적용할 수 있다. 통합·환경 담당과 `도착 → 진화 행동(위치·시간·자원량 등 합의 입력) → 환경 모델 효과 계산 → 새 state_version 및 ACK → 재관측 → 종료 판단` 계약을 합의하고 시연의 즉시 소화 경로를 조정한다. 문헌의 억제 계수, 소방차 진압 면적, 임의 셀 삭제를 ADAIR 값으로 넣지 않는다.

## 11. 팀 요청서의 필수 항목

모든 변경 요청은 `요청 ID / 현재 확인된 코드 / 차단 문제 / 계약 요청·응답 예시 / 단위·좌표계·시계 / source of truth / 오류·UNKNOWN / 수락 시험 / fixture 여부 / 실제 연동 상태 / 책임자`를 포함한다.

- **환경팀:** 단일 run, 원자적 읽기 snapshot, 명시적 advance/apply, 인제 map metadata·소방서 registry, valid DEM/NoData, 풍속·유효시간, 관측 ACK, 향후 suppression 모델. **화선 경계에 표시할 UNBURNED 위험지역 약 10칸**과 BURNING 셀을 동일 snapshot·격자 기준으로 제공하고, 셀 위치·크기/인접관계·점수·선정 기준(상위 10개인지, 경계 선택인지 등)·갱신/소멸 규칙을 명시해 달라고 요청한다. 백서 141쪽의 인제 주요시설(남전리 마을/마을회관, 인제휴게소, 위생환경처리장 등)을 **시설 후보**로 공유하고, 새 맵에 포함되는 위치/경계와 그 좌표의 별도 근거·레이어 제공 책임을 확인한다. 백서 그림의 픽셀을 실제 위경도로 취급하지 않는다. 개수는 협의 내용을 나타내며 현재 코드의 300개 제한이 이미 10개로 변경되었다는 뜻은 아니다.
- **UAV팀:** 단일 목표의 `지면 AMSL + target_agl_m(기본 80m) + 10m` 책임과 중복 가산 방지, UAV Agent의 DEM 직접 조회 방식 및 dataset/version/datum/NoData 계약, 100m 샘플링·±10m 허용오차의 검증 근거, route 전체 evaluate/execute와 ID/hash, 실제 도착·복귀·READY 증거, capability/경유지 지원 한계, COUNTER 구체 값, 실행 idempotency/조회, simulation time deadline 변환.
- **통합팀:** 공통 schema·배포 경계, 웹 → 총괄 → Local → Safety → Connector 흐름, 단일 환경 run 공유, 직접 UAV 호출 전환, 화면 도착과 실제 도착 분리, `/api/extinguish`·`/api/auto/done`의 즉시 `UNBURNED` 처리 전환, 공통 오류/상태 의미. 소방청 기준 보호대상 registry의 출처·버전, 새 맵 대상 레이어와 위험 셀의 같은 좌표계/버전 계약을 정한다. 웹에 위험도 점수와 보호대상·거리·총괄의 결정 이유를 표시할지 합의한다.

## 12. 시험과 상태 보고

총괄 단독 시험: 같은 접수 중복, 송신 전 저장 실패, Local REJECT, 구체값 없는 COUNTER 및 재평가 실패, Safety REJECT, route hash 변경, 풍속 누락, 목표 지면고도 누락 시 `TARGET_ALTITUDE_UNKNOWN`, 지면고도·80m·10m의 중복 가산 방지, 지도 밖/NoData, UNKNOWN 점유와 재전송 금지, 관측 완료와 복귀/READY 분리, mock 관측 미완료, 목적별 유효 관측·환경 ACK, 잘못된 LLM ID fallback, 실제 timeout과 simulation deadline 구분, 복귀 전 READY 금지. **화선 주변 UNBURNED 위험지역 약 10칸과 보호대상 위치의 시험 지도**를 넣어 동일 지도상의 경계 간 거리 계산·단위·순위 자료의 버전을 기록하는지, 대상 좌표 누락 시 계산을 보류하는지, 위험지역 변화에 따라 판단 근거를 갱신하는지, 위험 셀 하나마다 자동 출동하지 않는지 검사한다. 위험도와 거리가 충돌할 때 승인된 비교 규칙 없이 임의 가중치를 쓰지 않는지도 시험한다. 백서 142~146쪽을 바탕으로 기상악화 헬기 불가, 야간 전환, 주민 대피·민가 방어, 증원 요청의 **시나리오 사건과 판단 이유**를 각각 재생하되 당시 시점 이후의 결과 정보가 총괄 입력에 노출되지 않는지 확인한다. 실제 10칸·보호대상 레이어는 환경/통합 연동 후 따로 시험한다. 환경 반복 READ의 불변성은 fixture/adapter 수준과 실제 팀 환경 API 수준을 별도로 표기한다. 물리적 중복 실행 최대 1회·실제 PX4 waypoint·UAV DEM route·100m/±10m 기준·실제 맵·모의 관측 coverage·F1/F2 완료는 각 팀 계약과 통합 시험 전에는 통과로 적지 않는다.

결과 보고는 `A 구현 완료`, `B fixture로만 시험`, `C 팀 계약 대기`, `D 최종 발표 미완료`로 나눈다. branch·시작/종료 commit·수정 파일·시험 명령·성패·fixture·외부 연동 여부·blocker·다음 담당자를 기록한다. 이번 문서 검토는 **코드 수정 및 시험 실행 없음**이며, 이후 구현 보고와 혼동하지 않는다.

## 13. 연구 자료의 사용 범위

참고문헌은 *설계 구조를 검토하는 근거*다. 연구의 기체·센서·경로 숫자 또는 진화계수를 ADAIR 운영 규칙으로 가져오지 않는다. 단, §8의 **30×25m는 제조사 사양과 기하학 계산으로 출처를 밝힌 TEST_ONLY fixture**로 추가한다. 환경의 조회/step 분리, 경로 전체의 hard constraint, LLM 제안과 deterministic 검증의 분리, 관측 footprint의 센서 조건 의존, 진화 행동과 환경 효과의 분리, 동적 재평가를 채택 가능한 원칙으로 검토한다. 특히 `300m`, `15 waypoint`, `20초`, `risk 0.7/0.4`, 임의 소방차 수·진화계수는 운영 정책으로 설정하지 않는다.

## 사용자 결정이 필요한 사항

1. **소방청 보호대상 자료:** 공식 문서의 실제 우선순위 순서·적용일, 새 인제 맵에서 해당 보호대상 위치/경계와 출처를 확보한다. 현재 확인한 소방청 보도자료는 보호 분야를 설명하고 강원도소방본부 백서는 인제 사례의 주요시설·조치를 기록하지만, 둘 다 2026년 우선순위 간 수치 가중치와 실제 지도 좌표를 확정해 주지는 않는다.
2. **우선순위 입력 계약:** 환경팀의 화선 경계 위험지역 약 10칸의 선정·갱신 기준과 지도상 공간 관계, 긴급도/deadline/미관측 시각의 실제 제공 여부를 확인한다. 총괄은 위험도와 보호대상 거리를 계산·비교해 상황판단에 사용하되, 추가 근거 없이 진화 등급이나 소방차 대수를 결정하지 않는다.
3. **실제 수치가 필요한 때:** 기체 제원·지도 해상도·센서 profile·공식 자료·환경 모델 등 출처, 대안과 영향, 추천 이유를 먼저 제시하여 결정받을 것.
