## 1. R05 — UAV 단위와 상태 출처 확인

### 1-1. SDK 버전

| 항목 | 값 |
|---|---|
| Python | 3.14.4 |
| MAVSDK | `mavsdk` **4.0.0** (네이티브 바인딩, `requirements.txt`: `mavsdk>=4,<5`) |
| FastAPI / pydantic / uvicorn | 0.141.1 / 2.13.5 / 0.53.0 |
| PX4 | Docker `px4io/px4-sitl-gazebo:latest` (Gazebo Harmonic) |

3.x와 4.x는 API가 호환되지 않습니다. mavsdk 3.x 환경에서 real 모드를 띄우면 동작하지 않습니다.

### 1-2. 배터리 단위 — **0~100 (%)**

| 단계 | 값 | 비고 |
|---|---|---|
| PX4 원값 | 0~1 | MAVLink/PX4 내부 표현 |
| MAVSDK `remaining_percent` | **0~100** | SDK가 ×100 하여 제공. 2026-09-15 SITL 연결 실측에서 만충 시 `100.0` 확인 |
| UAV API `battery.percent` | **0~100** | `Px4Drone`이 변환 없이 그대로 전달 |
| evaluator / Mock | % 기준 | Mock 기본 95.0 |

- **변환 책임**: 원본 제공부(UAV)에서 이미 % 단위이므로 **UAV·통합 모두 추가 변환 불필요**합니다.
- 09-15 실측은 3.x 환경에서 한 것입니다. 4.x 환경의 원값·API 값 대조 로그는 real 서버 기동 시 함께 첨부하겠습니다.
- 신뢰도 주의: SITL 방전값이 100→95→88→93→100으로 되돌아오는 현상이 관찰됐습니다(포트 경합 상태 측정이라 재측정 필요). 소모율 `BATTERY_DRAIN_PCT_S = 0.033 %/s`는 추정치입니다.

### 1-3. endpoint와 모드

| resource_id | endpoint | 모드 | 상태 |
|---|---|---|---|
| A-uav1 | `http://3.37.210.229:8000` | real (PX4 SITL) | **평소 꺼둠.** 필요 시 UAV 담당에게 요청 |
| A-uav2, B-uav1, B-uav2 | 각자 로컬 (`http://localhost:800x`) | mock | 서버 배포 없음 |

- 비용 문제로 서버는 상시 운영하지 않습니다. 테스트는 로컬 mock으로 해 주세요 (`uav/README.md` 2번).
- 서버 모드는 `GET /health`의 `mode`, `uav_id`로 확인합니다.
- UAV 1대 = 프로세스 1개 = 포트 1개입니다. 경로의 `uav_id`가 서버 담당과 다르면 404를 반환합니다.
- ⚠️ 현재 IP는 고정(Elastic) IP가 아니어서 서버를 재기동하면 바뀔 수 있습니다. 바뀌면 기동 요청 시 안내하겠습니다.

### 1-4. 고정값·파생값 필드 — **총괄 가용성 근거로 사용 금지**

| 필드 | real 모드 실제 동작 |
|---|---|
| `health.failsafe` | 항상 `false` — PX4 health telemetry에 failsafe 항목 없음 |
| `link_quality` | 항상 `"OK"` |
| `current_task_id` | 이동·관측 중인 Task id. 대기·복귀 중에는 `null` (2026-09-29 수정) |
| `wind_ms` | 항상 `null` — 현재 PX4 SITL 구성에서 wind telemetry 미발행(실측) |
| `timestamp` | UAV 서버의 응답 생성 시각(ISO8601 UTC). PX4 텔레메트리 시각 아님 |
| `velocity_ms` | 수평 속도만 (N·E 성분) |
| `sensors_ok` | 자이로·가속도계·지자기계 캘리브레이션 플래그 AND |
| `position.alt_m_agl` | 이륙 지점 기준 상대고도. 실제 지면 기준 AGL 아님 |

따라서 Connector의 `state = OFFLINE if failsafe else READY`는 real에서 **항상 READY**입니다. 이는 Adapter 파생값이며 UAV가 확인한 가용성이 아닙니다.

### 1-5. mock과 real의 차이

요청에 `wind_ms`가 없으면 **mock은 내부값(3.1 m/s)으로 판단**하고, **real은 `REJECT / WIND_UNKNOWN`** 을 반환합니다. 통합에서는 항상 `wind_ms`를 실어 보내 주세요.

## 2. R01 — UAV 원본 응답 형식 (협조)

UAV 측 응답 스키마는 변경하지 않습니다(`uav/uav-agent/models.py`). 총괄 Adapter는 아래 형식을 그대로 보존하면 됩니다. 전체 사양은 [API_DEFINE.md](../../uav/API_DEFINE.md)에 있습니다.

### 2-1. 보존 대상 필드

| 응답 | 필드 |
|---|---|
| `/state` | `uav_id`, `timestamp`, `position{lat,lon,alt_m_amsl,alt_m_agl}`, `battery{percent,voltage}`, `velocity_ms`, `flight_mode`, `armed`, `health{gps_ok,sensors_ok,failsafe}`, `wind_ms`, `link_quality`, `current_task_id` |
| `/evaluate` | `task_id`, `decision_id`, `uav_id`, `verdict`, `eta_sec`, `reason`, `detail`, `counter_offer`, `constraints` |

- `task_id`, `decision_id`는 요청값을 그대로 echo합니다.
- **`eta_sec`**: ACCEPT·COUNTER는 정수(초)이고, 목표가 현재 위치와 같으면 **0이 나올 수 있습니다**. REJECT는 `null`입니다. 단 `LOW_BATTERY`는 `constraints.eta_sec`에 계산값이 있습니다.
- **`detail`**: 일부 REJECT에만 있고 나머지는 `null`입니다.
- **reason 코드**: 모두 `interfaces/schema.py`의 `RejectReason`에 등록되어 있습니다 (`FAILSAFE_ACTIVE`, `BUSY`, `WIND_UNKNOWN`, `MODERATE_WIND`, `DEADLINE_TIGHT` 포함).

### 2-2. MODERATE_WIND 판정 순서 — 총괄 정책 확인 요청

판정 순서는 다음과 같습니다.

```
WIND_UNKNOWN → FAILSAFE_ACTIVE → SENSOR_FAILURE → COMMUNICATION_FAILURE → BUSY
→ REQUIRED_CAPABILITY_UNAVAILABLE → HIGH_WIND(≥10) → LOW_BATTERY
→ RETURN_MARGIN_INSUFFICIENT(COUNTER) → TIMEOUT → DEADLINE_TIGHT(COUNTER)
→ MODERATE_WIND(COUNTER, 8≤wind<10) → ACCEPT
```

**풍속이 8~10 m/s여도 앞의 COUNTER 사유에 먼저 걸리면 `reason`은 그 사유로 나옵니다.** 이때도 풍속은 `constraints.wind_ms`에 남습니다. 총괄이 `reason == "MODERATE_WIND"`만 정책 수용한다면 이 경우는 수용되지 않습니다. 의도하신 동작인지 확인 부탁드립니다.

### 2-3. 응답 예시 (mock, 2026-09-29 재실행)

조건: A-uav1 원통119(38.1205, 128.2018, 235 m) → 목표(38.0425, 128.2541, 지면 804 m), `target_agl_m` 기본 80 m → 비행고도 894 m. 순항 10 m/s, 상승 3 m/s, reserve 15%. 배터리는 `/mock/set`으로 조정

```json
// GET /uav/A-uav1/state
{"uav_id":"A-uav1","timestamp":"2026-09-24T07:01:05Z",
 "position":{"lat":38.1205,"lon":128.2018,"alt_m_amsl":235.0,"alt_m_agl":0.0},
 "battery":{"percent":95.0,"voltage":15.8},"velocity_ms":0.0,"flight_mode":"HOLD","armed":false,
 "health":{"gps_ok":true,"sensors_ok":true,"failsafe":false},
 "wind_ms":3.1,"link_quality":"OK","current_task_id":null}
```

| 조건 | 결과 |
|---|---|
| wind 3.1, 배터리 100 | `ACCEPT`, `eta_sec: 1200`, `constraints.return_margin_pct: 18.8` |
| wind 9.0, 배터리 100 | `COUNTER / MODERATE_WIND`, `eta_sec: 1200`, `counter_offer: {"note":"풍속 주의. 고도 하향 권장"}` |
| wind 9.0, 배터리 95 | `COUNTER / RETURN_MARGIN_INSUFFICIENT` (**MODERATE_WIND 아님**), `constraints.return_margin_pct: 13.8`, `counter_offer: {"observe_duration_s":30,...}` |
| wind 12.4 | `REJECT / HIGH_WIND`, `eta_sec: null`, `detail: "wind 12.4 m/s exceeds limit 10.0 m/s"` |
| wind 3.1, 배터리 20 | `REJECT / LOW_BATTERY`, `eta_sec: null`, `detail: "need 81.2% but have 20.0%"`, `constraints.eta_sec: 1200` |

> 2026-09-29 수정: 아래 기준 변경으로 예시를 다시 실행했습니다.
> - 복귀 후 최소 잔량(`BATTERY_RESERVE_PCT`) 20% → 15%
> - 순항속도(`CRUISE_SPEED_MS`) 15 → 10 m/s. PX4 `MPC_XY_CRUISE`도 같은 값으로 설정 (기존에는 PX4가 기본 5 m/s로 비행해 예측과 불일치)
> - 비행고도 목표 지면 + 50 m → 지면 + `target_agl_m`(기본 80) + 10 m
>
> 그 결과 Mock 기본 배터리 95%에서 이 시나리오(편도 9.8 km)는 `ACCEPT`가 아니라 **`COUNTER / RETURN_MARGIN_INSUFFICIENT`(잔량 13.8%)**가 됩니다. ACCEPT 예시는 배터리 100%로 실행했습니다.

```json
// ACCEPT 전체 응답 (배터리 100)
{"task_id":"task-101","decision_id":"dec-001","uav_id":"A-uav1","verdict":"ACCEPT","eta_sec":1200,
 "reason":null,"detail":null,"counter_offer":null,
 "constraints":{"distance_km":9.81,"battery_now_pct":100.0,"battery_after_pct":18.8,"return_margin_pct":18.8,
                "wind_ms":3.1,"flight_alt_m_amsl":894.0,"required_climb_m":659,"eta_sec":1200}}
```
