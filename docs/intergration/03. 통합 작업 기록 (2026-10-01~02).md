- "자동 시작" 버튼: 박수진 님 답변(10/1) — 총괄의 "자동"은 신고·임무 접수 후 자동 판단·배정. 트윈 모드에서는 관제판 자체 자동 루프를 끄고 총괄(시나리오 신고 → 자동 정찰, 야간 순찰)이 맡는다. 단독 모드에서의 처리만 남았다.

### INT-05 시뮬레이션 시계 소유자 — 트윈 모드 완료 (`9778dc8`)

| 파트 | 시간이 가는 방식 |
|---|---|
| 산불 모델 | `step()` 호출 시 한 칸씩 진행. 확률·연소 지속이 스텝 단위이며 1스텝의 시간 길이는 정의되지 않음 |
| 관제판 | 브라우저가 화면을 갱신할 때 실제 1.5초마다 1스텝 (`WEB_ENV_STEP_SEC`) |
| `main.py`, `run_integrated.py` | 반복 1회 = 1스텝, 기록 시각 = 회차 × `SIMULATION_TIMESTEP_SEC`(1.0) |
| 총괄 (시험용 환경) | 1스텝 = 60초로 가정하나 진행시키는 곳이 없어 0초에 머묾 |
| UAV mock | 내부 100배속 |
| UGV sim | 실제 시계 기준, 시연용 속도 2,000 m/s (실속도 2 m/s) |

이미 정해진 것 (요청서 INT-05·ENV-01, 총괄 `config.py`): 시각 단위는 시뮬레이션 초, 0초의 실제 시각(`scenario_start_kst`)은 환경이 준다, 총괄은 읽기만 하고 시계 변화는 `/events ENV_UPDATED` 로 받는다.

합의할 것: ① 산불 1스텝 = 시뮬레이션 몇 초 (환경), ② 진행을 누가 얼마 간격으로 부를지 (환경·총괄·통합), ③ 화면 배속과 UAV·UGV 배속 맞춤 (전체).

멘토 패치 0004 가 답을 넣었다: 1스텝 = 2,100초(35분, 19시 소실 10 ha 보도에 맞춤), `/advance` 는 트윈 시계(`tools/twin_clock.py`) 하나만 부른다, mock 100배속 / real 1배속.

통합 쪽 반영 (`9778dc8`): `WEB_ENV_URL` 을 주면 관제판은 환경 계약 서버(8300) `/snapshot` 을 **읽기만** 하고 산불을 진행시키지 않는다. 이 모드에서는 관제판 자체 자동 루프와 진화 시연을 끄고, 기록 시각은 환경 서버의 시뮬레이션 시각을 쓴다(이전에는 수동 기록이 0.0 으로만 남았음). 상단 표시 `산불 시계: 환경 서버 (읽기만) / 관제판 자체`. 단독 모드(환경 서버 없이 관제판만)는 시연용으로 기존 방식을 남겼다.

### 서버 일괄 실행 `run_servers.py` (`e821e38`)

```
python run_servers.py start                    # UAV(8000) + 총괄(8200) + 관제판(8080)
python run_servers.py start --all              # + UAV2(8001), UGV(8100)

python run_servers.py start --demo-extinguish  # INT-02 시연 스위치

python run_servers.py start --twin             # 2019 인제 트윈: 환경(8300)·UAV 2·UGV·총괄(팀 환경)·관제판·시계·순찰
python run_servers.py status | stop [이름] | restart <이름>
```

서버 출력은 `logs/servers/<이름>.log`. 다른 터미널에서 직접 켠 서버와 포트가 겹치면 건너뛴다. 공동 수락시험(서버 끄기·재시작)에 그대로 쓴다. Windows 에서 켜기·끄기 확인.
