### INT-01 웹 출동 경로를 총괄 경유로 — 부분 완료 (`d154175`)

- 변경: `config.WEB_DISPATCH_VIA_ORCH` (환경변수로 켬, 기본 꺼짐). 켜면 "출동" 버튼이 UAV 에 직접 보내지 않고 총괄 `POST /tasks` 로만 보낸다 (정찰·UAV·열화상, 목표 위경도·지면 해발고도·칸 번호, 클릭마다 새 `request_id`). 총괄이 꺼져 있으면 실패로 답하고 UAV 로 우회하지 않는다.
- 화면: 상단 "출동 경로: 드론 직접 / 총괄 경유" 표시. 출동 후 로그창에 총괄 접수 결과, 총괄 판단 영역에 같은 임무가 나타난다.
- 실행 확인: 스위치를 켜고 출동했을 때 UAV 서버는 상태 조회만 받고 판단·실행 요청은 받지 않음.
- 현재 한계: 총괄이 시험용 환경이라 풍속을 몰라 `보류 · 보낼 자원 없음` 에서 멈춘다. 총괄 측 시나리오(기상·환경) 준비 후 공동으로 `TASK_RECEIVED → LOCAL_RESPONSE → SAFETY_JUDGEMENT → EXECUTION_SENT` 를 확인해야 한다.
- 남은 일: "자동 시작" 버튼. 박수진 님 답변(10/1) — 총괄의 "자동"은 신고·임무 접수 후 자동 판단·배정이며, 시뮬레이션 시작과 모의 신고 발생은 총괄 흐름에서 정리 예정.
- 확인: `tests/int01_orch_dispatch_check.py` 9항목.

### INT-05 시뮬레이션 시계 소유자 — 조사 완료, 대기

| 파트 | 시간이 가는 방식 |
|---|---|
| 산불 모델 | `step()` 호출 시 한 칸씩 진행. 확률·연소 지속이 스텝 단위이며 1스텝의 시간 길이는 정의되지 않음 |
| 관제판 | 브라우저가 화면을 갱신할 때 실제 1.5초마다 1스텝 (`WEB_ENV_STEP_SEC`) |
| `main.py`, `run_integrated.py` | 반복 1회 = 1스텝, 기록 시각 = 회차 × `SIMULATION_TIMESTEP_SEC`(1.0) |
| 총괄 (시험용 환경) | 1스텝 = 60초로 가정하나 진행시키는 곳이 없어 0초에 머묾 |
| UAV mock | 내부 100배속 |
| UGV sim | 실제 시계 기준, 시연용 속도 2,000 m/s (실속도 2 m/s) |

이미 정해진 것 (요청서 INT-05·ENV-01, 총괄 `config.py`): 시각 단위는 시뮬레이션 초, 0초의 실제 시각(`scenario_start_kst`)은 환경이 준다, 총괄은 읽기만 하고 시계 변화는 `/events ENV_UPDATED` 로 받는다.

합의할 것: ① 산불 1스텝 = 시뮬레이션 몇 초 (환경), ② 진행을 누가 얼마 간격으로 부를지 (환경·총괄·통합), ③ 화면 배속과 UAV·UGV 배속 맞춤 (전체).

합의 전 통합 쪽 준비로 확인된 것: 관제판의 산불 진행이 브라우저 갱신에 묶여 있음(탭을 닫으면 멈춤), 관제판 수동 출동 기록의 `simulation_time_s` 가 0.0 으로만 남음.

### 관제판 실행 모드 표시 (`5e6ab7a`)

관제판 상단에 `진화 시연: 꺼짐/켜짐`, `드론 서버: mock/real/연결 안 됨`, `출동 경로: 드론 직접/총괄 경유` 를 표시한다. 누를 수 없는 표시이며, 서버 시작 시 정한 설정을 보여 준다.

### 서버 일괄 실행 `run_servers.py` (`e821e38`)

```
python run_servers.py start                    # UAV(8000) + 총괄(8200) + 관제판(8080)
python run_servers.py start --all              # + UAV2(8001), UGV(8100)
python run_servers.py start --via-orch         # INT-01 스위치
python run_servers.py start --demo-extinguish  # INT-02 시연 스위치
python run_servers.py start --uav-url http://<IP>:8000   # 원격(real) UAV
python run_servers.py status | stop [이름] | restart <이름>
```

서버 출력은 `logs/servers/<이름>.log`. 다른 터미널에서 직접 켠 서버와 포트가 겹치면 건너뛴다. 공동 수락시험(서버 끄기·재시작)에 그대로 쓴다. Windows 에서 켜기·끄기 확인.

### 관제 로그 보강 (`6d291f5`)

| 이전 | 이후 |
|---|---|
| `ENVIRONMENT_UPDATE`·`TASK_COMPLETE` 에 `decision_id` 없음 | 판단 번호와 수행 자원 기록 |
| 수동 "출동" 기록 없음 | `TASK_CREATED → LOCAL_RESPONSE(판단 근거) → EXECUTION` (`MANUAL_DIRECT_NO_SAFETY` 표시) |

| — | 총괄 경유 출동 `ORCH_TASK_SUBMITTED` (접수/실패) |

모두 `logs/web_auto.jsonl` 에 남고 `detail.source` 로 출처(`WEB_MANUAL`, `WEB_AUTO`, `WEB_VIA_ORCH`)를 구분한다. 확인 스크립트가 실제 로그 파일을 지우던 문제도 고쳤다 (시험은 임시 폴더에 기록).
